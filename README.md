# Monitrail

Website uptime and performance monitor. Read `AGENTS.md`, then docs 01–06
in order before making changes. The current implementation is Phase 0 only.

## Local setup

Use Node.js 24.12.0 (`.nvmrc`) and npm 11.6.2. Install the pinned workspace
dependencies from the repository root:

```sh
npm ci
```

The root lockfile serves both packages; do not create package-level lockfiles.
`web/` is the Next.js App Router app, `checker/` is the Cloudflare Worker,
and `shared/` is reserved for later security modules and shared types.

Run from the root:

```sh
npm run dev --workspace web
npm run dev --workspace checker
npm run build
npm run lint
npm run typecheck
npm test
```

Both packages also expose `build`, `lint`, `typecheck` and `test` scripts
that can be run from their own directories. The Worker build is a local
Wrangler dry run, not a deployment. Its runtime types are generated by
`npm run typecheck`. The web typecheck generates Next.js route types first.
Biome supplies the shared recommended lint rules and React/Next.js rules
for the web app. TypeScript checks run separately.
The web scripts use Next.js's supported Webpack mode because Turbopack's
PostCSS subprocess could not bind its required local port in this environment.

Vitest intentionally has no application tests in Phase 0. Both test scripts
temporarily use `--passWithNoTests` for the specified empty-run check; remove
that flag when each package gains its first tests. Passing empty suites does
not verify application or security behavior. Playwright is installed for
browser smoke checks, with application smoke tests deferred to later phases.

## Environment and scope

Each package has a names-only `.env.example`. It is an inventory, not a
ready-to-use dotenv file: when a later phase needs credentials, create an
ignored `web/.env.local` or `checker/.dev.vars` and provide only the needed
`NAME=value` entries. Phase 0 builds and runs without credentials. Never
commit or print secret values.

The web app displays only its name and description. The Worker returns 404
and has no cron triggers, outbound requests, bindings or database access.
There is no database schema, authentication or monitoring implementation.
No project has been deployed or connected to a remote Git repository.

Tool telemetry is disabled in Next.js dev/build/start and Wrangler scripts.
The local Git identity is the project alias `Monitrail <dev@monitrail.invalid>`;
the reserved `.invalid` address is not a personal or deliverable email address.

See `docs/phase-0-verification.md` for dependency decisions, provider checks,
verification results and unresolved decisions for subsequent phases.
